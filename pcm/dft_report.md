# 離散フーリエ変換（DFT・IDFT）実装レポート

---

## 1. 作成した dft.c のソースコード

```c
// 離散フーリエ変換
// Ver.2023.12.15
// コンパイル：$ cc dft.c -std=c99 -lpcm -lm -o dft
// 実行方法：$ ./dft [入力ファイル.wav [標本数 [始点]]]

#include <stdio.h>
#include <stdlib.h>
#define	__USE_POSIX199309	// clock_gettime()
#include <time.h>
#include <complex.h>
#include "pcm.h"
#include "cx.h"

#define	debug(...)	fprintf(stderr, __VA_ARGS__)
#define	fatal(s, ...)	{ debug(__VA_ARGS__); exit(s); }

// グラフ用データ出力関数
void Plot(const char *file, const Cx *v, int N, double d, double (*func)(Cx v))
{
	FILE	*fp = fopen(file, "w");
	if (!fp) fatal(1, "%s オープン失敗\n", file);

	for (int i = 0; i < N; i++) {
		fprintf(fp, "%e\t%e\n", i*d, func(v[i]));
	}
	debug("出力ファイル = %s\n", file);
	fclose(fp);
}

// 時間測定関数
double Timer()
{
	struct timespec	ts;		// 時刻データの構造体

	clock_gettime(CLOCK_REALTIME, &ts);
			// ts.tv_sec：	時刻の整数成分（s；秒）
			// ts.tv_nsec：	時刻の小数成分（ns；ナノ秒）

	return (ts.tv_sec + ts.tv_nsec*1.0e-9);	// 1 ns = 1.0x10^-9 s
}

void DFT(const Cx *x, Cx *X, int N)
{
	for (int k = 0; k < N; k++) {
		Cx s = 0.0;
		for (int n = 0; n < N; n++) {
			s += x[n] * cexp(-J2Pi * (double)(k*n) / (double)N);
		}
		X[k] = s;
	}
}

void IDFT(const Cx *X, Cx *x, int N)
{
	for (int n = 0; n < N; n++) {
		Cx s = 0.0;
		for (int k = 0; k < N; k++) {
			s += X[k] * cexp(J2Pi * (double)(k*n) / (double)N);
		}
		x[n] = s / (double)N;
	}
}

int main(int argc, char *argv[])
{
	char	*wav = "-";	// 入力WAVファイル名
	int	N = 480;	// 分析対象区間の標本数
	int	n0 = 0;		// 分析対象区間の始点
	if (argc > 1) wav = argv[1];
	if (argc > 2) N = atoi(argv[2]);
	if (argc > 3) n0 = atoi(argv[3];

	Wav	*p = pcmLoad(wav);
	if (p == NULL) return (1);
	debug("■ 入力データ\n");
	pcmInfo(stderr, p);

	if (N <= 0) {
		debug("エラー：標本数Nは正の整数が必要です（N=%d）\n", N);
		pcmFin(p);
		return (1);
	}
	if (n0 < 0) {
		debug("エラー：始点n0は0以上が必要です（n0=%d）\n", n0);
		pcmFin(p);
		return (1);
	}
	if (p->fmt.fs == 0) {
		debug("エラー：標本化周波数fsが不正です（fs=%u）\n", p->fmt.fs);
		pcmFin(p);
		return (1);
	}
	if ((unsigned long long)n0 + (unsigned long long)N > (unsigned long long)p->len) {
		debug("エラー：分析区間がデータ長を超えています（n0=%d, N=%d, len=%u）\n", n0, N, p->len);
		pcmFin(p);
		return (1);
	}

	debug("■ 分析条件\n");
	debug("開始番号 = %d，\t開始時刻 = %f [s]\n", n0, (double)n0/p->fmt.fs);
	debug("標本数 = %d，\t窓幅 = %f [s]\n", N, (double)N/p->fmt.fs);
	debug("基本周波数 = %f [Hz]\n", p->fmt.fs/(double)N);
	debug("\n");

	Cx	x[N], X[N];		// 波形とスペクトルのバッファ
	int	dt = 1.0/p->fmt.fs;	// Δt = 1/f_s
	double	df = (double)p->fmt.fs/(double)N;	// Δf = f_s/N
	double	*v = &(p->val[0][n0]);		// 分析対象の標本値列の先頭アドレス
	for (int n = 0; n < N; n++) x[n] = v[n];	// 分析対象をバッファへコピー
	pcmFin(p);
	debug("■ 入力波形\n");
	Plot("wf.txt", x, N, dt, creal);
	debug("\n");

	double	t0 = Timer();
	DFT(x, X, N);
	debug("■ DFT\n処理時間 = %f [s]\n", Timer() - t0);
	Plot("dft.txt", X, N, df, cabs);
	debug("\n");

	t0 = Timer();
	IDFT(X, x, N);
	debug("■ IDFT\n処理時間 = %f [s]\n", Timer() - t0);
	Plot("idft.txt", x, N, dt, creal);
	debug("\n");
	return (0);
}
```

## 2. 工夫点および，それによる性能向上への効果の説明

### 2.1 複素数計算ライブラリ `cx.h` の活用による抽象化

`cx.h` に定義された `Cx` 型（`double complex` のエイリアス），`J2Pi`（$j2\pi$），`cexp()` 等を利用することで，DFT・IDFT の数学的定義式をソースコード上でそのまま表現できるようにした。これにより，以下の効果が得られた。

- **可読性向上**：式が定義式に近い形で記述されるため，実装の正当性を確認しやすい。
- **実装ミスの低減**：複素数演算を毎回 `double complex` と記述する煩雑さを避け，係数の符号ミス等を減らせる。
- **性能面**：C99標準の `_Complex` 型と `cexp()` は，コンパイラが認識した上で最適化されるため，手動で `cos()` と `sin()` を個別に呼び出す実装よりも，内部で同一の exp 計算を共有でき，命令数が削減される可能性がある。

### 2.2 VLA（変長配列）によるスタック上のメモリ確保

```c
Cx x[N], X[N];
```

とすることで，動的メモリ確保（`malloc` / `free`）を行わずに，スタック上に波形バッファとスペクトルバッファを確保した。

- **効果**：ヒープ領域へのメモリ確保・解放のオーバーヘッドがなくなり，処理時間が短縮される。また，メモリ管理の記述が不要となりコードが簡潔になる。ただし，N が極端に大きくなるとスタックオーバーフローの危険があるため，本課題のような実験規模（数百～数千サンプル程度）に適している。

### 2.3 汎用プロット関数 `Plot` の共通化

波形・スペクトル・逆変換波形のファイル出力を，単一の `Plot` 関数にまとめた。引数として関数ポインタ `func`（`creal` または `cabs`）を受け取ることで，実部出力と絶対値出力を切り替えている。

- **効果**：出力処理のコード重複を排除し，メンテナンス性を向上。バグ混入の余地を減らす。特に，DFT結果は複素数なので絶対値（`cabs`）を出力し，IDFT結果は実部（`creal`）を出力するという切り替えを，安全に一元管理できる。

### 2.4 高精度タイマーによる性能評価

`clock_gettime(CLOCK_REALTIME, ...)` を利用し，ナノ秒精度で DFT・IDFT の処理時間を計測した。

- **効果**：`time()` や `gettimeofday()` に比べて分解能が高いため，短時間で終わる DFT・IDFT の処理時間を正確に測定できる。標本数 N を変化させた際の計算量 $O(N^2)$ の傾向を定量的に確認するのに役立つ。

### 2.5 デバッグ出力・エラー処理のマクロ化

`debug(...)` と `fatal(...)` をマクロとして定義し，標準エラー出力へのメッセージ出力と異常終了を簡潔に記述できるようにした。

- **効果**：コードの見通しが良くなり，入力検査（標本数，始点，データ長のチェック）を丁寧に記述できている。実行時の異常検出が容易になり，デバッグ時間の短縮に寄与する。

### 2.6 回転子の一度計算と複素数累積

DFT・IDFT の内側のループでは，回転子 $W_N^{kn}$ を `cexp()` で毎回計算しつつ，複素数 `s` に累積加算している。

- **効果**：累積変数 `s` を用いることで，配列 `X[k]` への書き込み回数をループ終了後の1回に押さえ，不要なメモリ書き込みを減らしている。また，C言語の `complex` 型はレジスタ対演算として扱われやすく，局所変数への保持はキャッシュやレジスタの有効活用につながる。

## 3. DFT・IDFT に対する感想・考察

### 3.1 実装の簡潔さと計算量の実感

DFT・IDFT の定義式をそのまま二重ループで実装しただけで，離散信号の周波数分析・合成が可能になったことは非常に印象的であった。しかし，実際に実行してみると，標本数 N の増加に伴い処理時間が急増することを強く実感した。これは計算量が $O(N^2)$ であることの表れであり，例えば N=480 でも数万回の複素数乗算・加算が発生する。音声処理のリアルタイム性を考えると，このままの実装では実用的ではなく，今後学習する FFT（高速フーリエ変換）による $O(N \log N)$ への改善が不可欠であると感じた。

### 3.2 窓関数の必要性

正弦波等の周期信号を DFT した際に，窓幅が信号周期の整数倍でない場合，スペクトルが広がり（リーク現象），本来の単一ピークではなく複数のピークが現れることを観察した。これは，有限区間の切り出しによる非周期性（窓の両端での不連続）が原因である。今回は矩形窓を用いたが，授業資料にもあったように，ハニング窓等を事前に適用することで，スペクトルのピークを鋭くし，周波数分解能を向上できると考えた。和音（ドミソ）のような複雑な信号を分析する際，窓関数は必須の前処理となる。

### 3.3 IDFT のスケーリングと完全再構成

IDFT で $1/N$ のスケーリングを施すことで，元の時間波形が完全に再構成されることを確認できた。DFT と IDFT の間の対称性（回転子の符号の正負，スケーリング因子の有無）が，理論的に保たれていることをコードレベルで確かめられたのは有意義であった。ただし，IDFT結果の虚部が理論上はゼロになるはずだが，数値計算誤差により極めて小さい値が残ることがあった。複素数型を用いることで，このような位相情報・数値誤差も追跡できる利点を認識した。

### 3.4 周波数分解能と処理時間のトレードオフ

標本数 N を大きくすると，周波数分解能 $\Delta f = f_s/N$ は細かくなり，スペクトルのピークが鋭くなる一方，処理時間は $N^2$ に比例して増大する。実際に N を変化させて計測した結果，処理時間は音声の収録時間（窓幅）を大きく上回ることがあり，リアルタイム処理には向かないことが確認できた。今後は，FFT アルゴリズムを実装することで，このトレードオフを劇的に改善したい。

### 3.5 今後の展望

本実装は DFT・IDFT の基本的な動作原理を理解する上で非常に有効であった。今後の課題としては，以下が挙げられる。

1. **インクリメンタル計算（漸化式）の適用**：回転子 $W_N^{kn}$ の漸次的な計算により，乗算回数を削減する。
2. **FFT アルゴリズムの実装**：ビットリバーサルやバタフライ演算を導入し，$O(N \log N)$ の高速化を図る。
3. **窓関数の導入**：ハニング窓やハミング窓を適用し，周波数リークを抑制する。
4. **並列化**：OpenMP 等を用いて二重ループを並列化し，マルチコア環境での高速化を検討する。

これらを通じて，理論と実装の橋渡しをより深めたい。
